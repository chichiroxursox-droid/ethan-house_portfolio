# UX / Interaction Review

**Note:** Live Playwright testing blocked — Chrome profile already in use by another session. Review is code-only on the freshly-read source. Flagging this as a confidence hit.

## What works
- **Crosshair affordance is honest.** `explore.js:321-324` scales the dot 2x and tints it gold on a valid hit — gives clear "this is clickable" feedback at the reticle, exactly the FPS convention recruiters will recognize.
- **Universal Escape exit.** `main.js:228-239` routes Esc → MENU from COMPUTER/EXPLORING/ABOUT, and `explore.js:656-672` catches Esc in focus mode first via `capture: true`. Plus visible "ESC to exit" hint at `index.html:57`. Genuinely robust.
- **VN onboarding choreography.** `vn.js:121-153` paces sprite slide → dialogue fade → typewriter → choices stagger over ~2.6s — feels intentional, not a wall of buttons. Indoor music kicks in only when Ethan appears (`vn.js:135`), nice sensory crossfade.

## What doesn't work (ranked by visitor pain)
1. **Recruiter-fatal: scroll-to-meet-Ethan is 600vh of forced waiting** (`main.css:31`, gated by `progress >= 0.99` in `main.js:316`). A recruiter with 90 seconds will either bail or spam scroll without ever seeing the room. There's a "SCROLL TO EXPLORE" hint but no skip, no progress indicator, and the greeting only fires at 99% scroll — at scrub 1.5 (`scroll.js:48`) that's a multi-second wait *after* hitting the bottom. No "Skip intro" exit.
2. **Pointer-lock on entry to Explore is hostile.** `explore.js:850` calls `requestPointerLock()` immediately on enter, before the user opts in. On Mac this throws a system "Press Esc to exit" banner that makes the back button literally unreachable until they Esc — and then Esc *also* triggers the menu return (`main.js:235`), so they bounce out entirely. The "Click to look around" hint at `index.html:54-56` only appears *after* they've already been kicked out once.
3. **No discoverability for clickable objects until cursor crosses them.** Hover glow/crosshair (`explore.js:172-182`) only fires on raycast hit at screen center. There's no ambient highlight, list, mini-map, or "5 things to find" prompt. Visitor doesn't know basketball/piano/microphone/9 polaroids exist. They'll see "a room" and leave.
4. **Mobile is broken-by-design, not just unstyled.** Pointer-lock API is unsupported on iOS Safari; no `isMobile` branch anywhere (`grep` returned zero). Computer mode's canvas-rendered desktop UI uses `pointermove` hover (`computer.js:1289`) — touch has no hover. Chat input is a 320px-tall panel inside an `88vh max-height` modal — usable, but the rest of the experience silently fails. Recruiters often open links on phones first.
5. **Chat error swallowed; no retry.** `chat.js:89-91` shows "Sorry, something went wrong" and resets — no retry button, no "reach me at email" fallback link, no distinguishing 429-rate-limit vs network. If Groq is down during a recruiter visit, the AI-Ethan pitch dies silently.

## Top 3 improvements (by recruiter-conversion impact)
1. **Skip-intro / fast-path button.** Floating "Enter the room →" button visible on initial load that jumps straight to MENU state. Effort: S. Impact: high.
2. **Object discovery hint on Explore enter.** 4-second toast: "9 things to find — Microphone, Piano, Basketball, polaroids…" with subtle ambient pulse on each interactive's emissive for first 5 seconds. Effort: M. Impact: high.
3. **Mobile fallback page.** Detect `maxTouchPoints > 0`, swap to a tap-driven 2D project list + chat + email CTA. Don't try to port Three.js controls. Effort: M. Impact: high.
